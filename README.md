# 食来运转

中文趣味菜谱网站，主题是用一点小运气解决“今天吃什么”，并把选菜接到做饭、记录和朋友分享。

## 当前版本

- 手绘食物角色首页，适配手机、平板和桌面。
- 16 道原创整理的完整家常菜，支持菜名/食材搜索、分类、人数调整、步骤勾选和收藏。
- 每日幸运菜：按北京时间日期、用户/设备和候选菜集合稳定生成，给出幸运数字、菜色与真实食材。
- 2–6 扇区选菜转盘，禁忌食材和用时筛选先于抽取。
- 5 题美食人格测试，4 类趣味口味人格及对应推荐。
- 朋友帮选：真实持久化投票、一人一票可改投、分享链接、最近 20 场自己发起的投票。
- 饭饭日记：上传真实照片，选择私密保存或主动分享到小饭圈；支持删除自己的日记和点赞。
- 按菜谱与实际人份粗估热量，允许手动修正。

## 明确未接入

AI 照片识别没有连接任何图像模型。前端明确标注“待连接”，后端 `/api/estimate` 返回 503，`/api/kitchen?resource=me` 的 `aiAvailable` 为 false。没有假识别或随机热量。后续需确认模型服务、费用和照片传输目的地，再实现与连接实际服务。

新站保持 owner-private 权限。朋友投票与小饭圈功能需要先给朋友站点访问权限；站点代码不改变平台的访问范围。写入、个人数据与图片使用 Sites 登录身份，不使用客户端声明的身份。

## 技术与数据

- React + Vinext + Cloudflare Worker。
- D1 binding `DB`；schema 见 `db/schema.ts`，迁移见 `drizzle/`。
- R2 binding `BUCKET` 保存照片；上传元数据与所有权在 D1。
- 图片读取 `/api/image?key=...` 先检查所有权或关联共享动态，不开放 R2 公共链接。
- 上传限制：JPG/PNG/WebP、5 MB；服务端检查文件签名与尺寸。
- 设备偏好、未登录收藏存在浏览器；登录收藏、人格、日记和投票存在服务端。
- 菜谱热量为整份原料与用油粗估，显示时按人数换算；不是精密营养测量。
- 生成的首页插画与四道菜的示意配图在 `public/images/`。

## 开发与构建

使用仓库内现有锁文件安装依赖。开发 `npm run dev`；类型检查 `node node_modules/typescript/bin/tsc --noEmit`；生成迁移 `npm run db:generate`。Sites 发布遵循 Sites helper 流程，源码 manifest 在 `.openai/hosting.json`。不要在请求处理中修改数据库 schema。

生产由 Sites 负责登录与注入身份头。不能为方便测试添加生产环境的身份绕过开关。
